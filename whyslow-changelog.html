Changelog

All notable changes to this package are documented here.

The format follows Keep a Changelog. This package is 0.y.z: per Semantic Versioning, anything may still change. While on 0.x, a MINOR bump means a new capability, a PATCH bump means a backward-compatible fix.

[0.37.0] - 2026-08-26

Added

  • The hunt watches the managed heap and says the word Unity's own graph leaves to the reader. A heap graph beside the allocation sparkline shows the shape of the hunt, and a verdict reads the low points between collections: a sawtooth returning to its floor is healthy churn; a floor that keeps rising across recent collections "looks like a leak", with how much it rose. The bar is deliberately high — several collections, a long enough run, growth judged over the recent window so warm-up that settles is never accused — and when the evidence is thin the tab says so instead of guessing. No new measurement: the readings come from the recorders and collection events the pause tracker already had.

[0.36.0] - 2026-08-26

Changed

  • Stopping a hunt summarises what the live scan already collected instead of re-reading up to 300 profiler frames behind a progress bar. Stop is instant, a hunt of any length reports its whole duration, and frames the profiler's ring buffer had already evicted no longer silently vanish from the results. Card graphs are windowed to the last 240 frames and say so; every number covers the whole hunt.
  • The hunt's verdict is computed from one measurement, not two. Previously the "traced" count came from the last ~300 frames while the "scanned" totals came from the whole hunt, so a long session whose allocations happened early was reported as "Untraced" — sending the user to Deep Profile for garbage that was not there any more.
  • Six scene fixes left the one-click batch: shadow distance, shadow resolution, MSAA, terrain draw distances, realtime GI and reflection-probe refresh. Each changes what the player sees, or writes a project-wide setting judged from one open scene — the batch's own rule is that nothing in it needs to be looked at afterwards. Every one is still a single click on its own row.
  • The texture compression fix states its estimated saving, the way the audio and mesh fixes already did.
  • The "sizes describe the last build" note now appears after any importer fix — audio and mesh included, not just textures — and survives a domain reload; it clears when the next build is captured.
  • The report card states garbage per frame whenever two hunts exist, better or worse. A number that only appeared when it improved made every card silently flattering.

Fixed

  • Code inside a string interpolation hole is scanned again. $"{GetComponent<Foo>()}" was blanked along with the text around it, hiding a real per-frame lookup from every rule — and a string literal nested inside a hole could desynchronise literal tracking for the rest of the file.
  • Methods returning a multi-parameter generic — Dictionary<string, int> Foo() — are visible to the scanner again. The declaration pattern allowed no space after the comma, so the common style made the whole method invisible to the call graph.
  • CachedGetComponent<T>() — the helper the advice tells the user to write — is no longer re-flagged forever: the GetComponent and AddComponent rules now require the name to start at an identifier boundary.
  • Clicking Fix on a finding whose object was deleted after the scan no longer throws out of the window; the failure is logged and the re-scan reports what is actually there. The batch already behaved this way; the single fix and the wizard now match it.
  • A corrupted quarantine manifest — a crash mid-write can truncate it — no longer takes down the whole Project Assets tab from its constructor. It is reported to the Console and the quarantined files stay recoverable by hand or from the backup package.
  • A build-history file with an unreadable date no longer throws inside the diff view; the stored text is shown instead, matching how the overview already handles it.
  • Scene checks and Compile Time's Analyze run behind a cancelable progress bar. One scene rule reads project source files on its first run after a reload, and the assembly walk has frozen the editor on a large project before — both were uninterruptible.

Added

  • The Options menu can clear assets muted for the Import Watcher, with a count, like every other ignore list the tool keeps.
  • LICENSE.md in the package root, so the Package Manager's license view has something to show.
  • Tests for the hunt summary: outcome classification, whole-hunt averages, behaviour badges and the series copy, plus the interpolation-hole and declaration-pattern parser cases above.

[0.35.0] - 2026-08-20

Removed

  • The fixed-timestep rule. It compared two settings to each other and never looked at what physics costs, so it fired on a scene of 200 static colliders worth 0.08 ms a frame and stayed silent on 300 rigidbodies eating 9 ms of a 16 ms frame -- inverted against what matters. It also fired on Unity's own stock 0.02 timestep on every mobile scene containing any collider, telling a user who had changed nothing that their physics settings were wrong, and advising a value aimed at 30 fps to projects targeting 60. The frame rate it judged against came from Application.targetFrameRate, which in the editor is -1 until some play session sets it, so the verdict flipped between "warns on everything" and "never warns" depending on whether the user had entered play mode since the last recompile.

Fixed

  • Two hunts are now compared per second, each converted using its own recorded frame rate. Both used to be converted with the current hunt's, which restated the baseline at a rate it was never measured at: a project that went from 30 to 60 fps without changing a line generated twice the garbage per second and read as "no measurable change". A baseline recorded before the rate was stored is shown per frame instead of borrowing one, and says why.
  • Duplicate detection no longer groups empty files. Every empty file has the same length and the same content hash, so an empty script, an empty json and an empty placeholder arrived as one group of duplicates sharing nothing but being empty -- and a group of empty files frees zero bytes however it is resolved.

[0.34.0] - 2026-08-20

Added

  • Build X-Ray copies the current build's report to the clipboard: platform and date, the size that ships, each group's size and share, the largest assets, and the files the build wrote by kind. A treemap cannot be pasted into an issue.

Changed

  • Every share of a build is now taken against what the build actually ships -- the APK or AAB when there is exactly one, otherwise the written files minus IL2CPP's generated source and debug symbols. Unity's own total counts a package alongside the files compressed into it: a real Android build reported 1184 MB for a 256 MB install, which put "Resources is 16.9% of the build" out by more than four times. Where the two numbers differ the screen now states Unity's and why it is larger.
  • The overview, the history list and the two-build comparison all use that same number, instead of two of them quietly using Unity's.

Fixed

  • A build is recorded as soon as its asset list exists, rather than only once it has settled. A domain reload in between used to take the deferred pass with it, and the build was lost with nothing said -- which is why a second build could leave the tab still showing the first.
  • The tab notices a newer build on disk on its own, so it no longer depends on a notification surviving that same reload.
  • A successful build that packed no assets is reported instead of being recorded over the previous build's asset list.
  • A treemap tile too short for its stacked labels now shows its name instead of nothing.

[0.33.1] - 2026-08-20

Fixed

  • A logger the compiler strips was reported anyway. [Conditional("ENABLE_LOGGING")] on a method means every call to it disappears unless that symbol is defined — which is the whole point of writing one that way. In a project that defines it nowhere, the body cannot run, and the finding inside it was the only one in that scan with no guarded label: the most confident entry on the list and the only entirely false one. Such a method is now excluded like code behind a #if, and calling it does not make anything hot. Several attributes are an or, and one defined symbol is enough to keep it scanned.

Changed

  • The string-allocation advice no longer recommends a StringBuilder to code that already has one. sb.Append($"{a}{b}") builds the string before the builder ever sees it, so the fix is to append the parts, not to adopt a builder.

[0.33.0] - 2026-08-20

Five findings from a real project that were wrong in ways the list could not show.

Fixed

  • One statement counted several times. A log call whose interpolated parts are joined across three lines produced three findings — one allocation, three entries, and a headline count inflated by however many multi-line statements a project has. A rule now reports a given statement once, however many lines it spans.
  • Code that cannot compile into the player was reported anyway. Those findings sat inside #if ENABLE_DEBUG, in a project that defines ENABLE_DEBUG nowhere. Preprocessor conditions are now decided against the defines each assembly is actually compiled with, taken from the compilation pipeline — the project's own Scripting Define Symbols plus Unity's platform and version symbols. A symbol absent from that set is provably absent, not unknown. Where there is no assembly to ask, an unrecognised symbol still means "scan it", so nothing is hidden on a guess.
  • A coroutine's epilogue was reported as per-frame work. while (!request.IsFinished) yield return null; makes a coroutine genuinely repeating, and the whole method was then treated as hot — including the statements after the loop, which run exactly once. A repeating coroutine is now hot only across the loops that repeat.

Changed

  • Advice follows the situation where one pattern covers several. "Remove it" on a base class's protected virtual void Update() {} would break every subclass that overrides it, and is replaced by advice that says so. "Reuse objects with a pool" on Destroy(renderTexture) described resource cleanup as churn; Destroy without a matching Instantiate now names both possibilities instead of asserting the wrong one.

[0.32.4] - 2026-08-20

Fixed

  • Scan Code reported on a vendored copy of TextMeshPro. A team that needs to patch one of Unity's packages keeps a copy inside the project and references it by file path, which makes it Local -- for a reason that has nothing to do with who wrote it. The scan read that as "the user owns this" and read 59 of TextMeshPro's runtime scripts, pushing the user's own findings down the list; one category held a single finding and it was Unity's code. A package in Unity's own namespace is now never treated as the user's, however it is referenced. Anything outside that namespace stays in scope: guessing at who wrote com.somevendor.thing would risk hiding the user's own code, which is the worse mistake.

Changed

  • The scope note above the results says what is actually scanned -- your own code, wherever it lives -- instead of describing only which methods count as hot.

[0.32.3] - 2026-08-20

Changed

  • Scan Code asks the compilation pipeline which scripts to read, instead of walking the asset database and guessing. Two questions decide whether a script is worth reading -- does it reach a player build, and does it belong to this project -- and neither answers the other: URP, the Input System and TextMeshPro all ship to the player without being anyone's to fix, while an editor-only assembly is the user's code that never runs in a build. Both were being asked once per file, from the file's path, after enumerating the asset database to find the files at all. They are now asked once per assembly, and the file list comes from the assembly's own sources -- which is what the compiler will actually build. On this project that is 33 questions instead of 255, with no asset enumeration; the set of scripts scanned is unchanged.

[0.32.2] - 2026-08-20

Fixed

  • Scan Code enumerated every installed package before filtering most of them out. The search covered the whole "Packages" virtual root, which Unity resolves to every registry and git package's compiled scripts, not just the ones this project owns -- on a project with a normal package list that is thousands of GUIDs paid for and thrown away one by one. The search now covers Assets plus the asset path of each package actually Embedded or Local, so the scan no longer enumerates code it was always going to discard.

[0.32.1] - 2026-08-20

Fixed

  • The manual was never in the repository. Documentation~ matches the common *~ ignore rule, so the commit that added Documentation~/index.md committed everything except the file it was about. Anyone installing the package from git got no manual, and the Package Manager Documentation link led nowhere -- exactly the problem that commit said it had fixed. The file is tracked now, and the offline check fails if any file under the package is missing from git.
  • The manual described Import Settings as covering meshes and textures. It now covers the audio and texture-compression checks as well, including which of them deliberately refuse to batch.

[0.32.0] - 2026-08-20

A full audit of the package, and the fixes it produced. Two of these were the tool telling the user something that was not true.

Fixed

  • Half the import fixes could not actually be undone. The backup recorded three or four importer fields chosen when the first fixes were written; every fix added afterwards changed something outside that set, and Restore put back the fields it knew about while reporting success. Mipmaps, Read/Write, sample rate, force-to-mono, rig type and blend shapes were all in that gap. The backup now records an importer's complete permitted settings, for every platform, and carries a schema version so a record written by an older build is skipped rather than restoring a default over a setting it never captured.
  • Fix All in Import Settings discarded its own backups. It opened one backup operation per asset against a store that keeps the twenty most recent, so a run over thirty assets pushed its earliest entries out before it finished. One run is now one operation, one reimport batch and one undo step, and the backup is committed before the first setting is written.
  • Removing an assembly reference could not be taken back, though the screen offering it said it could. The original asmdef is now kept and there is a "Put it back" beside the removal. The edit is also confined to the references array — it matched anywhere in the file, so an assembly whose name matched its own rootNamespace had that line removed instead.
  • A GUID-form reference resolved to the asmdef's file name rather than the assembly's name. Where an asmdef had been renamed, a reference plainly in use was reported as unused, and the Remove button then did nothing.
  • The package did not compile on Unity 2021.3, which is the version it claims to support: the physics-simulation rule used an API added in 2022.2 with no fallback.
  • Dead Assets offered live assets for quarantine. Settings assets registered in Build Settings by packages such as the Input System or Localization, render pipeline assets assigned to a quality level, anything carrying an AssetBundle name, and shader includes were reachable from nowhere the scan looked. Scenes present in Build Settings but unticked are now roots too.
  • Plugins code was treated as editor code when deciding whether anything reads mesh or texture data at runtime, so a plugin that does read it was invisible and the Read/Write batch fix was offered anyway.
  • Quarantining could leave files unrecoverable. The manifest listed the whole plan before anything moved, so a move that failed part-way left Restore refusing the entire session — the files that had moved could not be brought back from the window at all.
  • Full garbage collections were never counted. Only the incremental collector's marker was matched, so a project with incremental collection turned off — the project the "turn it on" advice is written for — always read as having no collector pressure.
  • A clean project could not be reported as clean. The verdict was classified from a process-wide allocation counter that also reads the editor's own allocations, so a game that allocated nothing got a red "could not trace any of it" and was never saved as a baseline.
  • Clear brought back what it had just cleared. Scanning resumed from the oldest frame the profiler still held, so the loading-screen spike reappeared immediately.
  • Allocations past the first 4096 samples in a frame were dropped silently, which is most of them once deep profiling — which the tool itself recommends — is on.
  • The code scan misread ordinary C#. An expression-bodied member or an interface declaration claimed the next method's body, so cold code was reported as running every frame; a #if UNITY_EDITOR at the top of a file marked everything below it as conditional; a brace-less if or switch leaked into the following method; a literal ending in an escaped backslash swallowed the rest of its line; generic methods were invisible entirely. The parser now builds one map of the file that every check reads, and each of these has a test.
  • Four scan rules reported things that were not the problem: any + on a line with a string literal, the .material setter, PlayerPrefs keys, and Selectable.Select().
  • The window could not open at all if Library/WhySlow held an unreadable file. One tab failing to start no longer takes the other four with it.
  • The shader-timing pattern matched nothing on a real project, and re-read the entire editor log — which can reach hundreds of megabytes — on every build. It now reads only what the build itself wrote.
  • A build that packed nothing no longer records itself using the previous build's asset list.
  • Scene-view outlines follow an object while it is being moved.
  • Missing scripts, and every other scene rule, now see inactive objects.
  • The theme no longer leaks a set of textures on every skin change and domain reload.

Changed

  • "Safe to batch" now means safe without being looked at. Fixes that change what the game looks like, change how input behaves, or write a project-wide setting inferred from one open scene are still offered individually, but Fix All no longer applies them: physics simulation, far clipping plane, animator culling, WebGL compression. The raycast-target fix no longer treats a ScrollRect or a custom input handler as inert, and the mesh-collider rule no longer flags the kinematic case, which is valid.
  • The Build X-Ray texture fix only turns compression on. It also lowered Max Size and switched crunch on, both of which trade image quality for bytes — a decision the tool cannot make from here, and one this project's own notes had already ruled out.
  • Load Type is decided in one place. Build X-Ray judged it by clip length while Import Settings judged it by file size, and on ordinary clips each undid the other on every scan.
  • Cost to touch an assembly is now measured rather than modelled. It summed each affected assembly's solo compile time, which counted the fixed per-round overhead once per assembly, assumed Unity compiles them one after another, and could never price a hub at all — an assembly with dependents never compiles alone. It is now the median duration of the compilation rounds that actually started at that assembly. Domain reload is measured too.
  • Terrain detail is judged on the distances a user raises deliberately, not on Unity's own defaults, which the previous thresholds flagged on every fresh terrain.
  • Shadow distance and resolution under URP and HDRP read and write the pipeline asset. They read Quality Settings, which an SRP ignores, so the finding was wrong and the fix changed nothing.
  • WebGL checks stay silent outside a WebGL profile instead of passing with a false statement.

Removed

  • The mobile frame-pacing rule. It judged a project setting from Application.targetFrameRate read in the editor, which is a runtime value, and its premise — that VSync wastes frames on mobile — does not hold, because mobile platforms ignore VSync.

Added

  • The package has tests: 59 covering the code scanner's parser and its rules, each one pinned to a case that was previously wrong.
  • Preferences and Share report are documented, along with where backups live and what that means.

[0.31.2] - 2026-08-19

Fixed

  • The lossy-source check claimed every flagged clip gets re-encoded. That is true only when the clip is built to a compressed format; a clip stored as PCM is decoded once and kept, so the original encode is the only loss. The reason now names the format the clip actually builds to and says which of the two situations it is.
  • Cost to touch said "1 other assemblies rebuild with it", and reported an assembly nothing depends on as a count of zero rather than as the plainer fact that nothing else rebuilds with it.

[0.31.1] - 2026-08-19

Changed

  • Everything that folds is amber, everywhere: dead-asset branches, groups and subfolders, duplicate sets, import checks and code-scan categories. Terminal rows -- a single file, a single duplicate -- stay blue links. The colour now says the same thing the triangle does: amber opens, blue selects.

[0.31.0] - 2026-08-19

Removed

  • The quarantine tick boxes and the bulk button they fed. Every row -- branch, group, subfolder, file -- already carries a Quarantine button that acts on exactly what the row names, which is the same job done more directly: no state to build up, and no way to press a button whose meaning is spread across a screen you have scrolled past.

The explanation of what quarantine does, and the note that Restore All undoes one run at a time, stay where the button used to be.

[0.30.0] - 2026-08-19

Added

  • Four audio import checks, the category the tab had nothing to say about. Load Type against clip size, sample rate above the mobile ceiling, multichannel clips not forced to mono, and sources that are already lossy. All four come from the table in Unity's optimization guide.
  • Textures built without compression, which that guide calls the biggest win in its asset chapter -- its own comparison puts an uncompressed texture at roughly 26x the cost with little visible difference. The fix turns compression on and leaves the format Automatic: which compressed format is right depends on the oldest device a project supports, so the tool never writes ASTC, PVRTC or ETC2 into an importer on the developer's behalf.

Changed

  • A hot-path finding in a method that is only reached through a branch is now reported as Guarded rather than Confirmed. Being called from Update means the call site runs every frame, not the method -- an ad reload behind a countdown runs when the countdown expires.

[0.29.0] - 2026-08-19

Fixed

  • Scan Code reported allocations inside catch blocks as "per frame". Reaching a method from Update says the method runs every frame; it says nothing about its error handling. On a real project an ad manager's Update called a reload helper whose only flagged lines were the two log calls in its catch blocks -- code that runs when loading an ad fails, not sixty times a second. Lines inside a catch are now dropped rather than downgraded: if they really did run every frame, the exception would cost far more than the string.
  • The scope note claimed only Update, LateUpdate, FixedUpdate, OnGUI and coroutines were reported. The scan has always followed calls out of those, three levels deep within a file, which is why a finding could name a method the note said would never be scanned. It now says so.

[0.28.5] - 2026-08-19

Changed

  • Duplicates now reads like the rest of the window: each set of identical files is a foldout, the list is paged, and every path is a link that selects the asset. It was the last list still printing every member of every group as plain text with no separation, which is the one place it matters -- choosing which copy to keep means opening them.

[0.28.4] - 2026-08-19

Fixed

  • The texture check counted its findings as "9 meshes". The shared list widget hardcoded the vocabulary of the check it was written for, so every check that came later borrowed it -- textures, models and animation clips were all reported as meshes. Each check now says what it counts, and a single finding reads "1 texture" instead of "1 textures".

[0.28.3] - 2026-08-19

Fixed

The card's padding also pushed their buttons inward, so the two button columns did not line up. [0.28.2] - 2026-08-19

Changed

  • The Ignore folder menu is gone. It offered the folder and each of its parents, which existed only because the parents were invisible -- the list was flat and one third-party root produced six rows that all wanted the same single decision. The tree shows those parents as rows now, each with its own button, so the menu was offering a second way to do what is already one click above.

[0.28.1] - 2026-08-19

Fixed

  • Folder rows in the dead-asset tree were amber while the folder rows beneath them were blue. Both are the same thing -- a folder you open -- and they now look the same. Amber stays on the headings a section is filed under, which is the only job it had.
  • The three folder rows in that tree each carried their own copy of the arrow, the expand toggle and the link cursor. They share one control now.

[0.28.0] - 2026-08-19

Added

  • Dead-asset results nest by folder. A folder holding three or more groups now gets its own closed row, so a project with a content root reads as Assets/Addressables and Assets/Animations instead of thirty paths sharing a prefix and differing in the tail. Folders holding one or two groups are dissolved rather than turned into a level that hides almost nothing, and a folder containing only one other folder collapses into a single LevelEditor/Art row.
  • Import-settings checks fold. All five open closed, showing title and count, so the tab is an overview of what was found rather than the first check's results at full length.
  • Scan Code groups findings by pattern, each foldable and paged.

Fixed

  • Scan Code showed at most 60 findings and silently dropped the rest. Paging replaces the cap, so nothing found is now unreachable.
  • A check reporting 796 items pushed every later category off the end of a sixteen-page list. Texture import settings were there the whole time and effectively invisible.

Changed

  • Previous/Next pagers were written three times in three tabs and are now one control.

[0.27.2] - 2026-08-19

Changed

  • The row-level Quarantine buttons are amber, so the button that moves files no longer looks identical to the one beside it that only hides a row. Amber as an accent rather than a fill: the colour also carries section headings and the single bulk action, and twenty filled amber blocks down a list would leave none of the three meaning anything.

[0.27.1] - 2026-08-19

Fixed

  • The dead-asset scan crashed on any project with Addressables installed, and had since 0.26.1. Adding the progress bar moved the assignment of the published root summary to the end of a successful run, which was right, but Addressables detection wrote into that summary while the scan was still going -- so it wrote into null. The summary being built now travels as an argument, and the static holds finished scans only.
  • A failing scan took the window with it. The scan runs inside OnGUI between a BeginScrollView and its end, so an exception escaping into IMGUI left the layout stack unbalanced and Unity reported "Invalid GUILayout state" -- which names nothing that actually broke. The scan is now caught, logged, and reported in the tab as a failure that changed nothing.
  • The offline layout check counted BeginScrollView where a comment merely named it, leaving the scroll view open for the rest of the file and flagging every plain return after it.

[0.27.0] - 2026-08-19

Added

  • Dead-asset groups expand into a folder tree. Expanding a group used to spill every file beneath it into one flat column, which threw away the only structure available for judging them: a folder name is usually the whole reason a file is or is not still needed. Subfolders now nest and expand on their own.
  • Quarantine and Ignore on every level. A group row, a subfolder row and a single file row each carry both. The subfolder level is the one that was missing and the one most decisions actually happen at -- a group rolled up to a package root is too coarse to move in one go, and a single file is too fine to confirm two hundred times.
  • Quarantine no longer requires ticking boxes first. The tick boxes still drive the bulk button at the bottom; the row buttons act on what the row names, after the same confirmation.

Changed

  • Groups are listed alphabetically by path. They were ranked by how abandoned each folder looked, which reads as no order at all when hunting for a folder you recognise -- and every row already prints that share, so the ranking bought nothing the row did not say.
  • MoveToQuarantine moves exactly the candidates it is handed instead of filtering them by a selection flag. Three routes now lead there, and only one of them involves a tick box.

Fixed

  • Ignoring a folder left its files inside any group rooted above it. Only groups at or below the ignored path were dropped, so a surviving parent group kept listing files that had just been dismissed. Every removal now goes through one path that also rebuilds the affected tree.

[0.26.1] - 2026-08-19

Fixed

  • The dead-asset scan looked frozen. It ran to completion with no progress bar, so on a large project the window simply stopped repainting for as long as the scan took. It now names the phase it is in -- listing assets, reading scripts for Resources.Load paths, following dependencies from the protected roots, checking sprite atlases, classifying -- and can be cancelled.

Cancelling discards the run rather than showing what it got to. A scan stopped halfway has not found fewer dead assets; it has missed roots, and every asset those roots protect would be listed as unused. That list is worse than no list.

[0.26.0] - 2026-08-19

Added

  • Documentation. The package now ships Documentation~/index.md, which is what the Documentation link in Package Manager opens — it previously led nowhere. It covers what each of the five tabs answers, what quarantine actually does to your files, what is deliberately never reported as dead and why, what the tool cannot see, and where dismissals live.

Two sections exist because someone had to ask: quarantine was a word on a button that nothing defined, and the exclusion rules were invisible, so a finding that looked wrong had no way to explain itself.

Changed

  • The README described a three-tab tool. It now describes the five that exist, and links to the documentation.

[0.25.0] - 2026-08-19

Added

  • "Use Unity's default look" in Options. Every control falls back to Unity's own styling — buttons, cards, headings, the window background and the severity colours — for anyone who would rather the tool looked like the rest of the editor. A custom look is a matter of taste, and taste is not something a diagnostic tool should insist on. The choice is remembered, and the styles rebuild when it changes.

[0.24.0] - 2026-08-19

Added

  • Ignore a single file, next to each candidate. A folder was often too blunt: one deliberate leftover among live files should not require silencing everything around it. Kept by GUID, so the dismissal survives the file being moved or renamed, and listed with the ignored folders underneath.
  • An Options menu in the window header, holding the report and every dismissal the tool has been given — dead-asset ignores, skipped assets in Import Settings, assemblies marked not mine, and one item that clears all of them. Each shows its count. Dismissals are easy to make and easy to forget, and a tool told to stay quiet about enough things quietly stops finding anything; these counts are the only place that becomes visible.

Fixed

  • Dead Assets offered to delete the build's own configuration. google-services.json, GoogleService-Info.plist, link.xml, NuGet.config and packages.config were listed as unused. Unity, Gradle and Xcode go looking for these by name, so nothing references them and they are unreferenced by construction. The damage is invisible until it isn't: the Firebase files break it at runtime, and link.xml breaks only release builds, where code stripping then removes types nothing appeared to use. Matched by filename anywhere in the project, since link.xml legitimately appears in several folders at once.

[0.23.0] - 2026-08-19

Added

[0.11.0] - 2026-08-18

Added

  • Compile Time, a fourth tab, answering "why is my day slow" rather than "why is my game slow". Checkup inspects a scene, Build X-Ray a build, Performance Hunter a running game — none of them was about the wait between saving a script and being able to play again, which for a team past the prototype stage is the bigger number.
    • Cost to touch — each assembly priced by what rebuilds when you edit it: itself plus everything depending on it, timed from your own compilations.
    • Unused references with one-click removal, taken from the compiler's own output: it emits an assembly reference only where a type from it is used, so what an asmdef declares minus what its compiled output references is exactly the unused set.
    • Reference rings reported in full. Unity refuses to compile when assemblies form a ring but names only one participant; this names all of them, in order.
    • Editor code in a runtime assembly, which compiles fine in the editor and fails when someone makes a build.
    • Auto-referenced assemblies, which widen what rebuilds without appearing in any reference list a person can read.
    • Monolith and over-split triage — too much in one assembly, or so little in each that fixed per-compilation overhead is most of the cost.

Three things were measured rather than assumed while building this, and each changed the design:

  • Unity's per-assembly compile callbacks do not time compilation. assemblyCompilationStarted and assemblyCompilationFinished both fired within the same millisecond for an assembly whose compilation round took 819 ms, and the "not required" notices for everything else arrived 800 ms after the round began — the callbacks are delivered after the work. Timing between them measured 0.4 ms for a compile that really took 547 ms. Cost is now measured per round, and an assembly is only given a cost from rounds where it compiled alone, since splitting a shared round between assemblies would be a model presented as a measurement.
  • Assembly.assemblyReferences is not what the asmdef declares. It reports everything an assembly can see, auto-referenced assemblies included: an asmdef with "references": [] came back claiming four references. Declared references are now read from the asmdef file itself, so the tool never suggests deleting a line the user did not write.
  • A path under Packages/ does not mean the user can edit it. Registry packages report such a path while living read-only in Library/PackageCache. Before this was fixed the tool offered fixes for 66 assemblies in a project containing exactly two hand-written asmdefs.

Removing a reference rewrites only the matched line, leaving every other asmdef field byte for byte as written — verified by round-tripping a real asmdef and diffing it against the original.

Checked against Unity's own documentation and community practice: neither states or implies a bytes-per-frame acceptability number at all — the only guidance Unity gives is "ideally zero, as close as you can get." What the docs do describe is the actual mechanism: a collection is triggered by an allocation that cannot fit in remaining free heap space, so what matters is accumulation from repeated allocation, not the size of any single one. Significance is now judged by how often a call site recurs across scanned frames (at least 10% of them) rather than by its average size, which measures the thing the mechanism is actually sensitive to.

[0.3.0] - 2026-08-17

Added

  • Clear button in GC Hunter, next to Start/Stop Hunt. Forgets everything caught so far without ending the hunt — use it after a loading screen or menu so one-time setup allocations stop crowding out real gameplay offenders for the rest of the session. Recording, and the profiler configuration the hunt is using, are untouched.

Changed

  • "Caught so far" now shows offenders, not just whatever ranks highest. Found on a real project: a hint controller's search, gated behind a several-second UI idle timer, headlined the live panel at a fraction of a byte per frame while the project was, in truth, 99% clean. The measurement was correct — it really allocated that much, rarely — only presenting it as an offender was misleading. A call site is now named only when it is currently active or its lifetime average clears a real floor (64 B/frame, one sixteenth of the existing Warning threshold). Every site, named or not, still counts toward the total and the attributed percentage shown above the list.

[0.2.2] - 2026-08-17

Fixed

  • Project-settings findings (mobile frame pacing, shadow resolution, WebGL compression, and six others) offered a Show in Scene button that did nothing when pressed: their target is a persisted asset like QualitySettings, not a scene object, so the overlay had nothing to draw. [0.2.1] - 2026-08-17

Fixed

  • Scan code could attribute a finding to the wrong method entirely. Any statement shaped like return Foo();, throw Foo();, or await Foo(); was parsed as if it were declaring a method named Foo right there, and the next brace pair found afterward — typically an unrelated catch block — got mislabelled as that phantom method's body. Found on a real project: a finding reported as being inside IsInterstitialReady() was actually inside CanShowInterstitial(), a different method 1200 lines away. Declarations are no longer accepted when their leading token is a C# keyword that can never be a return type.
  • Fixing the above surfaced a second, older, unrelated gap caught by regression testing: a method written entirely on one line (void Poll() { Bar(); }) was invisible to every rule, because the code that measures a method's body treated "starts and ends on the same line" the same as "no body found at all."

[0.2.0] - 2026-08-17

Changed

  • The Scene Checkup tab is now Checkup, with a Scene / Code sub-view selector mirroring the one Build X-Ray already uses for Overview / Build Diff / Dead Assets. Scan code moved here from GC Hunter, where it was reachable but structurally out of place: it shares nothing mechanical with GC Hunter's live, Play-Mode-only measurement, while it shares everything with Scene Checkup — both are read-only checks that need no Play Mode. GC Hunter itself is unchanged; it goes back to being only what it says on the tab.

[0.1.1] - 2026-08-17

Fixed

  • GC Hunter's Scan code no longer treats every coroutine as a hot path. A coroutine now counts as hot only when a yield return sits inside a loop opened within its own body — a one-shot IEnumerator that yields once during setup and finishes is not a per-frame cost, even though it contains the word yield. Found via a false-positive pass against a real third-party project: 33 of 48 coroutines there were one-shot, not repeating, and all were being flagged.
